PyTorch08-PyTorch生态简介

八、PyTorch生态简介

前面几个章节已经学习了张量的基础知识、PyTorch 模型的常用组成部分与定义、模型的常规训练与验证/测试流程、模型可视化等内容，大家对基于 PyTorch 的深度学习已经有了初步的认知。回顾一下，前面学习过程中使用到的场景、示例大多是计算机视觉（CV）相关的，几乎一直在使用 PyTorch 官方开源的 torchvision 这个计算机视觉包。虽然一直在使用，但并未从整体上对 torchvision 做过一个完整系统的总结，这正是本章节要做的事情之一。

此外，PyTorch 自 2016 年由 Meta 公司（原 Facebook）开源并发布首个 Alpha 版本以来，迅速流行并逐渐确立了主流地位。一方面得益于 Meta 强大的推广与 PyTorch 框架本身极佳的设计与易用性，而另一个核心原因则是 PyTorch 生态的包容性与完整性。

在 PyTorch 首个开源版本发布后，官方针对不同的垂直领域（视觉、文本、音频、视频）先后推出了四大核心扩展库：torchvision、torchtext、torchaudio 和 pytorchvideo。这些核心扩展库的推出极大地便利了相关应用的开发，并有力地促进了 PyTorch 生态的繁荣与推广。

本章节学习的主要内容正是：对 torchvision、torchtext、torchaudio 和 pytorchvideo 这几个核心扩展库进行系统性的总结与介绍。

每个扩展核心库的内容较多，此处只会对针对其中主流常用或具有代表性的子包或工具进行阐述，要继续深入研究其中某个子包的功能或特性，可以参考其官方文档展开。

8.1 torchvision介绍

torchvision是PyTorch官方开源的计算机视觉扩展库，其中提供了当前研究与开发中常用的与计算机视觉处理相关的功能：图像数据集加载（如 MNIST、CIFAR、ImageNet）、经典模型架构（ResNet、VGG 等）以及丰富的图像变换与数据增强工具（transforms），此外其还提供了 解码/编码图像与视频（io）、运算符/损失函数和层（ops）、 各种实用工具程序（utils）等相关子包及功能。

torchvision的官方文档：https://docs.pytorch.org/vision/0.21/，其中文版本的镜像化文档：https://pytorch.ac.cn/vision/0.21/。

8.1.1 图像数据集加载torchvision.datasets

官方文档地址：torchvision.datasets 文档 。

8.1.1.1 内置数据集

Torchvision 在 torchvision.datasets 模块中提供了许多内置数据集，以及用于构建自定义数据集的实用工具类。

所有数据集都是 torch.utils.data.Dataset 的子类，即它们都实现了 __getitem__ 和 __len__ 方法。因此，它们都可以传递给 torch.utils.data.DataLoader。

所有数据集都有几乎相似的 API。它们都有两个共同的参数：transform 和 target_transform，分别用于转换输入和目标。

具体的数据集列表见：torchvision 0.21.0中内置数据集 。

8.1.1.2 自定义数据集类

还可以使用PyTorch提供的基类创建自己的数据集。官方提供了如下几个基类，供自定义数据集类时继承。

8.1.1.3 wrap_dataset_for_transforms_v2

在 PyTorch 中，可以使用 wrap_dataset_for_transforms_v2 适配新版数据增强。

在 PyTorch 视觉库的演进中，torchvision.transforms.v2 引入了极其强大的联合数据增强能力（即可以同时对图像、目标检测框 boxes、分割掩码 masks 以及关键点 keypoints 进行同步的空间几何变换，如随机裁剪、水平翻转等）。

然而，许多传统或经典的数据集（例如 CocoDetection）在设计时，其返回的标签格式是原生的 Python 列表或字典，无法直接被现代的 v2 管道所识别。为此，官方提供了 wrap_dataset_for_transforms_v2 工具来无缝解决这一兼容性问题。

8.1.2 经典模型架构torchvision.models

官方文档地址：torchvision.models官方文档。

torchvision.models 子包包含用于解决不同任务的模型定义，包括：图像分类、像素级语义分割、目标检测、实例分割、人体关键点检测、视频分类和光流（针对这些不同类型的模型，torchvision.datasets中提供了对应的内置数据集）。

为了方便使用者，PyTorch官方已经在torchvision.models 子包中收纳了许多module与model，具体可参考： torchvision/models ，也可以在源码文件torchvision/models/__init__.py中查看，可直接下载。同时为每个model也提供了多个可选的预训练权重，可供直接下载。

8.1.3 图像变换与数据增强torchvision.transforms

官方文档：https://docs.pytorch.org/vision/0.21/transforms.html。

torchvision.transforms 是 PyTorch 中用于计算机视觉任务的核心模块。虽然它常被称为数据增强工具包，但严谨地说，其提供的图像变换操作主要包含两大核心类别：

  1. 基础预处理 / 数据清洗（Preprocessing）

    • 操作：如将图像转换为 Tensor 并归一化、调整尺寸等。
    • 主要目的：这是让数据“符合模型胃口”的必要步骤，它不改变数据的多样性，通常在训练集、验证集和测试集中均会使用。

  2. 狭义的数据增强（Data Augmentation）

    • 操作：如随机水平翻转、随机裁剪、色彩抖动等。
    • 主要目的：专门用于训练集，通过不断制造视觉“扰动”来扩充样本空间、防止模型过拟合，从而有效提升模型在未知场景下的泛化能力（注意：测试集通常绝对不能使用这类随机增强操作）。

通过组合各类图像变换手段，该模块不仅能将原始图像转换为模型所需的格式，还能支持图像与标注（如检测框、分割掩码）的同步几何变换，从而有效丰富训练数据并提升模型的泛化能力。 备注：数据增强 只是从其最终使用场景与目的来说的，其底层执行的操作仍然是图像变换。

由于版本迭代更新，PyTorch其实为torchvision中数据变换与数据增强提供了两个版本的API：V1（torchvision.transforms）、V2（torchvision.transforms.v2）。V2 API是于2023年初发布的torchvision 0.15中首次引入的，提供了更多的功能且运行更快，是PyTorch官方推荐的现代版本。由于历史原因，网络上和各个开源项目中仍存在大量使用 V1 的代码，新版 torchvision 仍对其提供支持（就是说，即使是最新的 torchvision 0.29 也未将torchvision.transforms子包删除）。

8.1.4 解码/编码图像与视频torchvision.io

官方文档地址：https://docs.pytorch.org/vision/0.21/io.html。

torchvision 0.21 中，torchvision.io提供了视频、图片文件的 IO 操作的功能，包括读取、写入、编解码处理操作。比如图像解码（decode_image）、图像编码（encode_png）、读写文件（read_file、write_file），有不同 API 支持视频解码，但提醒用户torchvision.io中视频解码功能后续将 移到另一个独立的开源项目 torchcodec ，且这个动作最终在 torchvision 0.29 中正式落地。

TorchCodec 是一个基于 PyTorch 的原生库，可以用来做视频、音频、图像的解码与编码操作，在CPU与NVIDIA GPU上都能用。此项开源项目的旨在提供更快、更易用的相关操作，并与PyTorch生态无缝集成。

8.1.5 运算符/损失函数和层torchvision.ops

官方文档地址：https://docs.pytorch.org/vision/0.21/ops.html。

torchvision.ops 实现了计算机视觉特定的运算符、损失函数和层。所有运算符都原生支持 TorchScript。

它是 PyTorch 中专门为计算机视觉任务提供的高效、专有运算操作模块。它包含了许多底层且计算密集的算子（如非极大值抑制 nms、RoI 池化与对齐 roi_align、roi_pool 等），并支持 GPU 加速，是构建目标检测、实例分割等高级视觉模型不可或缺的核心工具包。

8.1.6 各种实用工具程序torchvision.utils

torchvision.utils 是 PyTorch 中用于计算机视觉任务的实用工具模块。它主要提供了一系列辅助性功能（如图像网格拼接 make_grid、将图像张量保存为文件的 save_image 等），常用于模型训练过程中的可视化、调试以及结果输出，极大地简化了图像数据的展示与保存流程。

8.2 torchtext简介

官方文档地址：https://docs.pytorch.org/text/stable/index.html。

首先说明：官方已于 2024 年 4 月（发布 0.18 版本后）宣布停止活跃开发并将该库归入维护阶段。在当前的深度学习与 NLP 实际开发中，社区和官方均已全面转向使用 Hugging Face 生态（如 transformers、tokenizers 等） 作为绝对的主流替代方案。因此，在现代 PyTorch 项目中通常不再依赖 torchtext。

torchtext 是 PyTorch 官方曾经用于自然语言处理（NLP）的核心数据与工具库，旨在为文本任务提供一站式的预处理和管道支持。

torchtext 的核心与组成如下：

  • 数据集（Datasets）：内置了许多经典的 NLP 基准数据集（如 IMDb、AG_NEWS、SST-2 等）的加载接口。
  • 文本处理与词表（Transforms & Vocab）：提供分词器（Tokenizer）、词表构建（Vocab）以及词向量（Word Embeddings）加载工具。
  • 预训练模型（Models）：曾集成如 RoBERTa、T5、Flan-T5 等经典 Transformer 模型的架构与官方预训练权重。

如果有需要，关于torchtext的使用可参考：https://github.com/atnlp/torchtext-summary、https://datawhalechina.github.io/thorough-pytorch/%E7%AC%AC%E5%85%AB%E7%AB%A0/8.4%20%E6%96%87%E6%9C%AC%20-%20torchtext.html，以及官方文档与示例。

8.3 torchaudio简介

官方文档地址：https://docs.pytorch.org/audio/2.6.0/index.html、https://docs.pytorch.org/audio/2.11.0/index.html。

Torchaudio 是一个使用 PyTorch 进行音频和信号处理的库。它提供了信号和数据处理功能、数据集、模型实现以及应用组件。

从 Torchaudio 2.8 版本开始，其已过渡到维护阶段。因此存在如下变更

  • 部分 API 在 2.8 中被弃用，并自 2.9 起被移除。
  • PyTorch 对音频和视频的编解码能力已整合到 meta-pytorch/torchcodec 中。 详情可参见 https://github.com/pytorch/audio/issues/3902。

8.3.1 主要组成部分

在 torchaudio 2.6.0中，各子包的精简介绍及其在 torchaudio 0.11 中的状态：

  • torchaudio：提供核心的音频加载、保存与元数据查询功能。在 torchaudio 0.11 中已作为核心顶层命名空间存在。
  • torchaudio.io：提供音频与视频的流式输入/输出编解码功能。此功能在后续版本中逐步被废弃并转移到 meta-pytorch/torchcodec。
  • torchaudio.functional：提供无状态的音频信号处理和数学运算函数。在 torchaudio 0.11 中仍存在并广泛使用。
  • torchaudio.transforms：提供基于 torch.nn.Module 的有状态音频变换与数据增强模块。在 torchaudio 0.11 中仍存在。
  • torchaudio.datasets：提供常用公开音频数据集的便捷下载与加载接口。在 torchaudio 0.11 中仍存在。
  • torchaudio.models：提供常见音频任务的神经网络模型架构定义。在 torchaudio 0.11 中仍存在。
  • torchaudio.models.decoder：提供用于语音识别任务的解码器及搜索算法组件。在 torchaudio 0.11 中仍存在。
  • torchaudio.pipelines：提供集成预训练模型及其配套预处理逻辑的封装流水线。在 torchaudio 0.11 中仍存在。
  • torchaudio.sox_effects：提供基于 SoX 库的音频效果链处理与应用工具。在 torchaudio 0.11 中仍存在。
  • torchaudio.compliance.kaldi：提供与 Kaldi 兼容的音频特征提取实现。在 torchaudio 0.11 中仍存在。
  • torchaudio.kaldi_io：提供用于读取和写入 Kaldi 数据格式的轻量级封装工具。在 torchaudio 0.11 中仍存在。
  • torchaudio.utils：提供各种辅助性实用工具函数。在 torchaudio 0.11 中仍存在。

8.3.3 torchaudio.datasets的使用

torchaudio 已经收纳了一些常用的音频相关开源数据集，可以直接下载使用；同时，如果要对开源数据集进行自定义使用或对自定义音频数据集进行封装使用，仍是先继承torch.utils.data.Dataset来自定义数据集类，然后将数据集实例传递给torch.utils.data.DataLoader进行数据的加载与获取。

8.3.4 models与pipelines的使用

官方文档地址：https://docs.pytorch.org/audio/2.6.0/installation.html、https://docs.pytorch.org/audio/stable/models.html。

torchaudio.models 子包包含用于解决常见音频任务的模型定义，比如：HDemucs、Conformer、ConvTasNet、DeepSpeech等。对于具有预训练参数的模型，参考 torchaudio.pipelines模块。

torchaudio.pipelines 模块将预训练模型与支持函数和元数据打包成专门用于执行特定任务的简单 API。

当使用预训练模型执行任务时，除了使用预训练权重实例化模型外，客户端代码还需要以训练时相同的方式构建用于特征提取和后处理的管道。这需要传递训练过程中使用的信息，例如变换的类型及其参数（例如，采样率和 FFT 频元数）。

为了使这些信息与预训练模型绑定并易于访问，torchaudio.pipelines 模块使用了 Bundle 类 的概念，该类定义了一组用于实例化管道的 API 以及这些管道的接口。下图展示了这一点。

预训练模型和相关管道表示为 Bundle 的实例。相同 Bundle 的不同实例共享接口，但其实现并不限制为相同类型。例如，SourceSeparationBundle 定义了执行声源分离的接口，但其实例 CONVTASNET_BASE_LIBRI2MIX 实例化了一个 ConvTasNet 模型，而 HDEMUCS_HIGH_MUSDB 实例化了一个 HDemucs 模型。尽管如此，因为它们共享相同的接口，所以用法是相同的。

8.3.5 transforms与functional的使用

transforms官方文档：https://docs.pytorch.org/audio/stable/transforms.html。 functional官方文档：https://docs.pytorch.org/audio/stable/functional.html。

torchaudio.transforms 模块包含常用的音频处理和特征提取。torchaudio.functional 模块则包含了一些用于执行常用音频操作的函数。

torchaudio中的变换（Transforms）是使用 torch.nn.Module 实现的。构建处理管道的常用方法是定义自定义 Module 类，或者使用 torch.nn.Sequential 将多个 Module 链接起来，然后将其移动到目标设备和数据类型。 类比下，torchvision.transforms中通过创建Compose实例（其中传入多个要执行的变换操作）来创建数据变换管道，然后再使用Compose实例做数据变换，个人感觉，torchaudio中这样的设计方案为音频数据的变换提供更大的灵活性与功能复杂性（torchaudio.transforms也已经内置了许多音频数据变换实现），但也提升了设计复杂性与门槛。

8.3.6 compliance.kaldi与和kaldi_io的使用

官方文档：https://docs.pytorch.org/audio/stable/compliance.kaldi.html。

Kaldi 是一个用于语音识别研究的工具箱，由CMU开发，开源免费。它包含了构建语音识别系统所需的全部组件，是语音识别领域最流行和影响力最大的开源工具之一。torchaudio中提供了一些与 Kaldi 工具兼容的方法，这些方法分别属于torchaduio.compliance.kaldi，torchaduio.kaldi_io。

8.3.6.1 torchaduio.compliance.kaldi

在torchaudio.compliance.kaldi中，torchaudio 提供了以下三种方法：

  • torchaudio.compliance.kaldi.spectrogram：从原始音频信号创建语谱图。
  • torchaudio.compliance.kaldi.fbank：从原始音频信号创建滤波器组（fbank）。
  • torchaduio.compliance.kaldi.mfcc：从原始音频信号创建梅尔频率倒谱系数（mfcc）。

8.3.6.2 torchaduio.kaldi_io

torchaudio.kaldi_io是一个 torchaudio 的子模块，用于读取和写入 Kaldi 的数据集格式。当我们要使用torchaudio.kaldi_io时，我们需要先确保 kalid_io （这是一个轻量级的 kaldi_io 包装器，用于返回 torch.Tensors）已经安装。

torchaudio.kaldi_io主要提供了以下几个接口：

  • torchaudio.kaldi_io.read_vec_int_ark：从 Kaldi 的 .ark 文件、压缩文件、管道或已打开文件对象中逐条读取“键名 + 整数向量”，并返回 PyTorch Tensor。
  • torchaudio.kaldi_io.read_vec_flt_scp：按照 Kaldi .scp 索引文件提供的位置逐条读取“键名 + float32/float64 浮点向量”，并返回 PyTorch Tensor。
  • torchaudio.kaldi_io.read_vec_flt_ark：从 Kaldi 的 .ark 文件、压缩文件、管道或已打开文件对象中逐条读取“键名 + float32/float64 浮点向量”，并返回 PyTorch Tensor。
  • torchaudio.kaldi_io.read_mat_scp：按照 Kaldi .scp 索引文件提供的位置逐条读取“键名 + float32/float64 浮点矩阵”，并返回 PyTorch Tensor。
  • torchaudio.kaldi_io.read_mat_ark：从 Kaldi 的 .ark 文件、压缩文件、管道或已打开文件对象中逐条读取“键名 + float32/float64 浮点矩阵”，并返回 PyTorch Tensor。

奇怪的是，torchaudio.kaldi_io 的源码在 torchaudio 2.8及之后还存在，但 torchaudio.kaldi_io 的介绍与使用在 torchaudio 2.8及之后的官方文档中并不见了。相关描述只能从源码或以前版本的官方文档中查看。

8.4 pytorchvideo简介

PyTorchVideo （官方开源地址：https://github.com/facebookresearch/pytorchvideo） 是一个专注于视频理解任务的深度学习开源工具库，由 Meta（原 Facebook）AI 研究院（FAIR）专门为视频理解（Video Understanding）领域开发并2021年中左右开源。它提供了可复用、模块化且高效的组件，以加速视频理解领域的研究。PyTorchVideo 基于 PyTorch 开发，支持多种深度学习视频组件，如视频模型、视频数据集以及针对视频的特定变换操作。是 PyTorch 生态的重要组成部分。

相关论文见：PyTorchVideo: A Deep Learning Library for Video Understanding ，发表于2021年11月。

8.4.1. 核心定位与设计目标

与专注于通用图像任务的 torchvision 不同，PyTorchVideo 专门聚焦于时空（Spatiotemporal）视觉数据。其核心设计目标包括：

  • 模块化与可重用性：提供标准化的视频模型架构、损失函数和评估指标，避免开发者每次都要从头实现。
  • 高效的数据处理（Efficient I/O）：针对视频文件体积大、解码慢的痛点，提供高性能的视频解码与数据加载管道（支持多线程、硬件加速等）。
  • 开箱即用的预训练模型：集成了一系列主流的视频分类、动作识别和时空检测模型及官方预训练权重。

8.4.2. 核心功能与模块组成

  • 视频数据转换与增强（Transforms）：支持丰富的时空几何变换，例如同时对视频帧序列进行时间戳抽帧、空间裁剪、随机翻转、色彩调整等。
  • 经典/前沿视频模型（Models）：内置了大量顶尖的视频理解模型架构，例如：
    • SlowFast：Meta 提出的经典双通路视频动作识别模型。
    • X3D：高效轻量化的视频网络架构，适合移动端或算力受限的场景。
    • CSN (Channel-Separated Networks)、MViT (Multiscale Vision Transformers) 等基于 Transformer 的现代时空架构。
  • 高效的视频 I/O 管道：针对视频解码优化，能够无缝集成到 PyTorch 的 DataLoader 中，减少数据传输瓶颈。

8.4.3. 生态现状与独立性

  • 独立的项目生命周期：PyTorchVideo 采用了独立的开源仓库和独立的官方文档网站（pytorchvideo.org），没有作为子包合并到 torchvision 中。
  • 应用场景：它广泛应用于短视频内容分析、安防监控、体育动作评析、自动驾驶视频感知等需要对“时间序列图像”进行深度理解的业务与科研场景中。
