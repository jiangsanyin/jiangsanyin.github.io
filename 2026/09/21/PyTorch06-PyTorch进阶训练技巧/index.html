6.1 自定义损失函数

尽管PyTorch官方针对主流模型为用户提供了很多内置损失函数，但随着应用场景的变化与自定义模型的出现，那些内置损失函数可能并不适合，于是产生了一些针对非通用模型的损失函数。有些损失函数是针对某特定场景使用，可以直接拿来使用或修改使用，有些场景或自定义模型甚至找不到现成或逼近的损失函数可用，此时就需要自定义损失函数。

本章节学习的内容包括：如何自定义损失函数。

6.1.1 以函数形式定义损失函数

损失函数其实就是用来计算模型输出数据与真实数据之间的差距的，所以计算损失的过程就是一个函数执行的过程。 所以理论上来说，可以通过定义一个函数的形式来自定义损失函数。

6.1.2.2 Dice Loss损失函数

Dice 相似系数（Dice Similarity Coefficient，简称 DSC） 是图像分割（如医学图像分割 UNet）领域中最核心的评价指标之一。 基于该系数构造的损失函数被称为 Dice Loss。

6.1.2.2.1 公式及各项符号的含义

公式： \[DSC = \frac{2\vert{}X \cap Y\vert{}}{\vert{}X\vert{} + \vert{}Y\vert{}}\]

  • \(X\)：通常代表模型预测的分割区域（Prediction Mask）。
  • \(Y\)：通常代表真实的标签区域（Ground Truth Mask）。
  • \(\vert{}X \cap Y\vert{}\)（分子）：\(X\) 与 \(Y\) 的交集大小（即模型预测正确且属于真实目标的像素/前景数量）。乘以 \(2\) 是为了进行归一化平衡。
  • \(\vert{}X\vert{} + \vert{}Y\vert{}\)（分母）：\(X\) 的像素元素总数与 \(Y\) 的像素元素总数直接相加。
  • \(DSC\) 的取值范围：在 \(0\) 到 \(1\) 之间。
    • \(DSC = 1\)：代表预测区域与真实区域完全重合（完美分割）。
    • \(DSC = 0\)：代表预测区域与真实区域没有任何重合。
6.1.2.2.2 从 DSC 指标到 Dice Loss

神经网络训练时需要最小化 Loss（损失越小越好），而 DSC 是越大越好。因此，在代码中定义 Dice Loss 时，通常采用以下两种转化方式之一： \[\text{Dice Loss} = 1 - DSC = 1 - \frac{2\vert{}X \cap Y\vert{}}{\vert{}X\vert{} + \vert{}Y\vert{}}\] 或者使用负数形式： \[\text{Dice Loss} = -DSC\] 方式一是最常用形式。这样，当分割效果越好（\(DSC \to 1\)）时，\(\text{Dice Loss}\) 就越接近 \(0\)。

6.1.2.2.4 为什么分割任务中非常喜欢用 Dice Loss？

普通的交叉熵损失（Cross Entropy Loss）是对所有像素一视同仁地计算误差。如果在医学图像中，病灶（前景目标）只占全图的 1%，背景占了 99%（严重的前背景极度不平衡），模型即使把所有像素都预测为背景，准确率也能达到 99%，但这种模型是无效的。

Dice Loss 关注的是前景与真实区域的交叉重叠比例，它天然消除了背景像素占绝大多数带来的影响，能够极大地改善类别不平衡（Class Imbalance）问题。

6.1.3 为什么常用“类”的形式

既然定义一个普通函数就行，那什么情况下需要把 Loss 写成继承 nn.Module 的类呢？主要有以下 3 个场景：

  • 损失函数包含状态或超参数（Hyperparameters） 比如之前写的 DiceLoss(smooth=1.0) 或 CombinedLoss(alpha=0.5)，如果写成类，可以在 __init__ 中把 smooth 或 alpha 保存为成员变量，调用时只需传 criterion(output, target)，接口更加统一规范。

  • 损失函数包含“可学习参数”（Learnable Parameters） 有些高级损失函数（如某些自适应损失、感知损失、带有可训练权重系数的多任务 Loss），Loss 内部自己也带有需要随训练更新的 nn.Parameter。此时必须使用 nn.Module，这样 model 和 loss 的参数才能一起被传给优化器（Optimizer）：

  • 兼容 PyTorch 标准生态管道 许多高级训练框架（如 PyTorch Lightning、HuggingFace Trainer）内部要求 criterion 必须是一个 nn.Module 实例，方便统一进行 .to(device) 设备迁移或数据并行（DataParallel）。

大致的经验就是： - 临时测试、无状态计算、简单数学组合 \(\rightarrow\) 用函数形式 def my_loss(...)（简洁、高效、写起来最快）。 - 模块化封装、包含可调参数/可学习权重、需要对接通用训练框架 \(\rightarrow\) 用继承 nn.Module 的类。

6.2 动态调整学习率

在使用PyTorch编写神经网络模型并进行训练时，如何确定一个合适的学习率或学习率调整策略是一个比较关键的问题。 使用固定的学习率时的话，如果将学习率设置得太小，学习模型参数更新太慢，可能使网络模型在既定总轮次下无法收敛到最佳状态，如果直接增加训练轮次将当于人为增加了训练时间；如果将学习率设置得过大，则模型参数更新过快，可能导致模型无法精准落入收敛区甚至在最优解两侧来回跳动、无法收敛。

为此，人们想到了根据实际情况不断自动更新学习率的学习率调整策略（学习率scheduler）。最常见最简单的学习率调整策略是：在训练初始时将学习率设置恰当大（这大概率需要使用固定的学习率提前训练一轮或几轮，提前摸查下模型的收敛情况），然后随着训练轮次的增加不断减少学习率（比如每20轮将学习率变更原来的1/2）。 当然，也有更新复杂的随实际情况更新学习率的学习率调整策略。PyTorch中内置了很多不同的学习率调整策略；此外，还可以根据需要自定义学习率调整函数或策略。

6.3 模型微调torchvision

本节学习的内容包括：模型微调的流程、PyTorch中内置的主要开源模型、如何训练模型的指定层。

6.3.1 微调相关背景介绍

开源社区已经为大家提供了很多针对各种场景下使用的神经网络，其中很多神经网络训练时采用了大规模、高质量的数据集，但它们终归只是考虑到了当时场景。大家在实际学习工作时，会遇到各种不同实际业务场景，经当时的数据集训练得到的神经网络一般情况下并不能直接应用。

对于一般小型团队或公司而言，项目中能够收集到的训练、测试数据集规模相对较小，相比而言开源社区很多结构复杂的大规模神经网络如ViT使用的数据集则大得多，比如ImageNet系统数据集至少是百万个样本数据。如果直接采用这些”开源神经网络的结构+自己的目标数据集“，很可能会造成过拟合，同时因为此时的目标数据集小太多可能训练得到的最终模型精度（如准确率、泛化能力等）达不到实用程度。 （当然如果某开源模型当时就是由小规模数据集或跟自己当前的目标数据集规模度差不多甚至更小训练得到的，理论上是可能直接拿此开源模型的结构从头开始训练，更新得到目标数据集上的全新权重参数，从而得到一个新的目标模型。）

为此，对于这类大规模神经网络，要想使用它们的结构（甚至进行少量改动），并利用自己当前已有的目标数据集训练、更新权重参数，有如下两种常见的方法：

  • 将目标数据集规模、质量扩大或提升至开源的大规模神经网络当时使用的数据集一致。但收集与标数据集是一个成本非常高的过程，其成本大小与数据集规模、质量呈正相关关系，所以这一过程意味更高的成本，这对于一般的小团队或公司是不可取的。
  • 使用应用迁移学习（transfer learning），将开源模型在源数据集上学习到的能力迁移到目标数据集上。它的机理是：开源模型使用的源数据集跟目标数据集可能很大程度并不一致或不是描述同类事物，但开源模型在源数据集能够学习到抽象通用的图像特征（比如图像的纹理、边缘、形状与颜色等），它们也适用于目标数据集。

模型方面，应用迁移学习的最常用、最典型应用场景就是模型微调（finetuning）。模型微调的大致意思是：复制某个开源模型（包括模型结构与权重参数），在目标数据集上重新进行训练、不断更新其模型权重参数，使其能够在目标数据集表现达到预期。就是说我们站在巨人的肩膀上，利用优秀开源模型的骨架，赋予其目标数据集的灵魂，使模型与数据完美融合获得预期的涌现能力。

掌握模型微调，可以快速验证问题、提升模型与数据融合能力。

6.3.2 微调在 PyTorch 中的两类典型操作

在实际编写 PyTorch 代码时，根据目标数据集的大小，模型微调通常分为两种具体策略：

  1. 特征提取（Feature Extraction / 冻结骨干）：
    • 操作：把开源 Backbone 中除了最后输出层外的所有层参数全冻结（param.requires_grad = False），只训练我们自己新加的最后一层分类头（Linear）。
    • 适用：目标数据集非常非常小（比如只有几百张图）时。

具体描述此策略下模型微调的流程如下：

  • 1）获取源模型：在源数据集（一般是大规模开源数据集）上训练得到源模型。这个工作一般开源社区已经帮忙完成了。
  • 2）构建目标模型：复制源模型中除了最后的输出层外的模型结构与权重参数，并手动构建、添加一个输出与目标数据集一致的新输出层，新输出层的权重参数是随机初始化的。
  • 3）更新新输出层：将目标模型中新输出层前面所有的层的权重参数冻结，在目标数据集上进行训练、更新新输出层中的权重参数。
  • 4）测试与保存目标模型：当目标模型测试达到预期后，将其以文件的形式持久化保存下来以备后用。如果测试不通过，则重复2）、3）、4）这几个步骤。

  1. 全量/部分微调（Full/Partial Fine-tuning）：

    • 操作：加载预训练权重，用很小的学习率（如 \(10^{-4}\) 或 \(10^{-5}\)）对整个网络（或后半部分深层网络）的所有参数进行端到端的梯度更新。
    • 适用：目标数据集有一定规模（几千到上万张图）时，也是最标准的微调方式。 在“全量/部分微调”的具体步骤中，通常比“特征提取”多一个学习率差异化（Layer-wise Learning Rate） 的细节：
  • 在进行全量微调时，由于 Backbone 已经具备了很好的通用特征，而新替换的输出层（Linear）是随机初始化的：
    • 新输出层：可以使用正常的学习率（如 \(10^{-3}\)）快速收敛。
    • Backbone 预训练层：必须使用极小的学习率（如 \(10^{-5}\) 或 \(10^{-4}\)），避免更新幅度过大直接“破坏”掉原本已经在海量数据上学好的通用特征提取能力（这在学术界被称为“灾难性遗忘”或“破坏预训练特征”）。

6.5 半精度与混合精度训练

6.5.1 半精度与混合精度训练的背景

GPU 的性能主要由算力（Flops，在特定精度下的矩阵乘加运算吞吐量）与显存（包括容量大小与显存带宽）共同决定。对于一张确定的物理 GPU，其峰值算力与显存硬件规格是固定的。

显存作为 GPU 板载的高速存储介质，用于在计算过程中高速暂存模型参数、输入数据及中间激活结果。 在GPU算力范围内，GPU单次能接受的输入数据量越多（常以增加batch_size值大小体现），通常意味着单个轮次模型训练所需要的迭代步数越少、模型训练总耗时越少。GPU内显存中默认是以float32单精度浮点数暂存各种数据的，模型训练的一个轮次中，在float32单精度情况下当batch_size增大一定程度时，输入数据需要的显存可能达到GPU显存的临时存储上限，如果此时所需的GPU算力还未达到GPU的算力上限，为了进一步压榨GPU的计算能力与显存临时存储能力、提升模型的训练效率，可以float16半精度浮点数的形式将数据送入GPU显存中，此时同样的源数据只需要占据使用float32时的大约一半GPU显存空间，所以能使得batch_size最大增加为原来的2倍左右、提升模型的训练效率。

但因为float16相比float32使用了更少的比特位来存储数据，指数位数与小数位数都更少，所以能表达的数据范围也更小。但对于一般的模型训练场景下用float16来存储数据已经够用了，所以对于一些单样本占据数据量比较大（如3D图像、视频等）、数据集总样本数很多的场景，使用半精度进行模型训练仍然一种常用的提升模型训练效率的方法。

关于float32与float16的相关示意图如下： 可以看到：

float32单精度使用4个字节存储一个数据，其中符号位、指数位、小数位使用的比特位数分别是：1、8、23 。存储的数据范围是：\(-3.40 \times 10^{38} \sim 3.40 \times 10^{38}\) 。

float16半精度使用2个字节存储一个数据，其中符号位、指数位、小数位使用的比特位数分别是：1、5、10 。存储的数据范围是：\(-65504 \sim 65504\) 。

如果float16表达的数据范围不够用的，但又不想使用float32，也可以使用BF16，它能够表达的数据范围与float32几乎一致，只是减少了尾数位、牺牲精度。

此外，在实际的大模型或深度学习训练中，如果单纯直接将所有数据和参数都转换为 FP16 进行训练，很容易遇到数值不稳定（如梯度消失或梯度溢出）的问题。为了解决这一问题，业界普遍采用 AMP（Automatic Mixed Precision，自动混合精度） 策略——在前向/反向传播中采用 FP16/BF16 进行矩阵计算以提升效率，同时在后台维护一份 FP32 的主权重并结合动态梯度缩放（Loss Scaling）来保证数值稳定性，兼顾了训练效率与模型精度。

6.5.3 混合精度训练及示例

混合精度训练（Automatic Mixed Precision，简称 AMP） 是现代深度学习训练（尤其是大语言模型 LLM 和 Vision Transformer）中用于大幅提升训练速度并显著降低显存占用的标准工程实践。

深度学习中的现代混合精度训练（Mixed Precision Training）方法是由百度（Baidu）与英伟达（NVIDIA）的研究团队于2017年底联合提出，论文见：https://arxiv.org/abs/1710.03740。

它的核心思想非常简单：在对精度不敏感的大规模计算环节使用 低精度数据类型（FP16/BF16） 来换取算力和显存效率，而在对数值范围敏感的参数更新环节保持 高精度数据类型（FP32） 来确保模型的收敛与稳定性。

6.5.3.1 为什么需要混合精度？

  1. FP32（单精度浮点数）的局限：
    • 显存大、算力未跑满：FP32 占用 4 字节。当模型参数量达到数亿或数十亿时，FP32 会迅速榨干 GPU 显存。
  2. 纯 FP16（半精度浮点数）的致命缺陷：
    • 数值范围过窄（\(-65504 \sim 65504\)）。FP16 的指数位只有 5 位，最小正数约为 \(6.10 \times 10^{-5}\)。
    • 梯度下溢（Underflow）与上溢（Overflow）：反向传播计算出的微小梯度低于 \(10^{-5}\) 时会被直接清零（下溢，变为 0）；如果数值大于 65504 则会溢出（变为 Inf/NaN），导致模型无法训练。

为了兼顾 FP16 的极速/省显存 与 FP32 的稳定性，混合精度训练（AMP）应运而生。

6.5.3.2 混合精度训练（AMP）的核心运行机制

AMP 通常由以下三个核心技术环节协同工作。以 PyTorch 原生 AMP 为例，模型参数默认仍保存为 FP32；autocast 不会把整个模型永久转换为 FP16/BF16，而是按算子临时选择合适的计算精度：

1. 前向与反向传播（按算子选择低精度）
  • 计算载体：输入和模型参数无需预先整体转换为 FP16/BF16。进入 autocast 上下文后，PyTorch 会为每个算子选择精度：卷积、矩阵乘法等兼容算子通常以 FP16 或 BF16 计算；归约等数值敏感算子则保持 FP32。中间激活值的实际 dtype 也因此取决于产生它的算子。
  • 硬件加速：在支持 Tensor Core 的 CUDA GPU 上，低精度矩阵乘法和卷积通常能提升吞吐量，并降低部分激活值的显存占用；实际加速比例取决于 GPU、模型结构、批量大小和数据输入瓶颈，不能保证固定倍数。
2. FP32 模型参数与优化器状态
  • 更新载体：在 PyTorch 原生 AMP 的常见用法中，模型通过 model.to(device) 保持 FP32 参数，Adam/AdamW 等优化器的状态也通常随 FP32 参数以 FP32 保存。
  • 作用：优化器直接用这些 FP32 参数进行更新，避免把参数永久存为 FP16/BF16 后的频繁舍入误差。某些其他框架或手动 model.half() 的实现会维护独立的“FP32 主权重”副本，但这不是 torch.autocast 的默认工作方式。
3. 动态梯度缩放（Dynamic Loss Scaling，针对 FP16）
  • 机制：在反向传播前，将损失函数（Loss）乘以一个较大的放大因子 \(S\)（Scale Factor），强制将极小的梯度拉回到 FP16 的表达范围内，避免下溢。
  • 还原：GradScaler.step(optimizer) 会在调用优化器前还原梯度，并检查是否出现 Inf/NaN。若发现溢出，则跳过本次参数更新，并由 GradScaler.update() 动态调小 \(S\)。

6.5.3.3 FP16 AMP 与 BF16 AMP 的选型对比

存储格式 字节数 指数位 / 尾数位 表达数据范围 稳定性与特点 适用场景
FP16 AMP 2 字节 \(5\text{ bit} / 10\text{ bit}\) \(-65504 \sim 65504\) 精度略高，但范围小；必须开启 GradScaler（损失缩放）。 传统 CV 视觉模型、较早期的 GPU（如 V100/T4/20系）

6.5.3.4 混合精度训练的工程优势

  1. 显存消耗显著降低（减少约 40% ~ 50%）：
    • 占显存大头的数据（激活值、中间张量）全部变为 16 位，允许提升 1.5~2 倍的 batch_size。
  2. 训练计算速度大幅提升（通常 1.5x ~ 3x 加速）：
    • 极大地缓解了 GPU 显存带宽瓶颈（Memory Bandwidth Bound），同时全面释放了 Tensor Core 的矩阵计算吞吐量。
  3. 模型最终精度几乎无损：
    • 由于关键的权重更新与损失计算依然运行在 FP32 精度下，模型的收敛曲线与最终准确率/Loss 与全 FP32 训练高度吻合。

6.6 数据增强

6.6.1 数据增强的背景与必要性

训练集数量有限时，模型可能记住训练图片的背景、拍摄角度或噪声，而不是学到类别真正具有的特征。这种“训练集表现很好、未见过的数据表现变差”的现象称为过拟合。收集更多真实且正确标注的数据通常最有效，但在医学图像、工业缺陷检测等场景中，采集和标注成本很高。

数据增强（data augmentation）是在训练时对已有样本施加合理变换，从一张训练图片生成不同但语义相同的训练输入。例如，一张猫的照片经轻微裁剪、左右翻转或亮度变化后，标签仍然是“猫”。这样可增加训练输入的多样性，使模型不那么依赖某个固定位置、亮度或背景。

数据增强并不是越强越好。变换必须符合任务的真实规律：自然图像分类中的轻微裁剪、翻转和颜色扰动通常合理；对“左右”本身有语义的任务、文字识别或医学影像，随意翻转、旋转或改变颜色可能改变标签含义。验证集与测试集用于模拟真实未见数据，通常只做确定性的尺寸调整与归一化，不应使用随机增强。

旧教程常使用 imgaug。它的维护已长期停滞，在 Python 3.12 / NumPy 2 等新环境中可能难以安装或兼容。当前 PyTorch 图像任务中，推荐优先使用与 PyTorch 紧密集成的 torchvision.transforms.v2；当任务包含目标检测框、分割掩码、关键点等多种标注，或需要更丰富的增强算子时，Albumentations 也是常见选择。

6.7.1 深度学习的超参数是什么

在深度学习中，超参数（Hyperparameter） 指的是在模型开始训练之前，由开发者手动设定并指定的参数配置。与之相对的概念是参数（Parameter）。以下给出了深度学习中超参数与参数简单比较：

概念 定义 谁来决定？ 典型例子
超参数 (Hyperparameter) 控制模型结构或训练过程的外部配置项 人为手动设定（凭经验或调优算法） 学习率、Batch Size、网络层数、Epoch 次数
参数 (Parameter) 模型在训练过程中通过数据自动学习和更新出来的权重值 模型自己学（通过反向传播和梯度下降） 神经元的权重 \(w\)、偏置 \(b\)

6.7.1.1 经典超参数分类

超参数大致可以分为以下两类：

6.7.1.1.1 控制“训练过程”的超参数（优化超参数）

这类超参数决定了模型怎么学、学多久、学多快：

  • 学习率（Learning Rate, \(lr\)）：最重要的超参数之一。决定了每次更新权重时的步长大小。步长太大容易无法收敛（跳过极小值），步长太小训练速度太慢。
  • 批次大小（Batch Size）：每次送入网络进行计算和梯度更新的样本数量（如 32, 64, 128）。
  • 训练轮数（Epochs）：整个数据集被模型完整遍历训练的总次数。
  • 优化器（Optimizer）选择：如 SGD、Adam、AdamW 等。
  • 损失函数权重 / 正则化系数（Weight Decay / L2 Regularization）：用于控制正则化强度，防止模型过拟合。
  • 随机种子（Random Seed）：控制权重初始化、数据 Shuffle 和 Dropout 等所有随机行为的起点，用于确保训练过程和实验结果的可复现性。
6.7.1.1.2 控制“网络结构”的超参数（结构超参数）

这类超参数决定了模型长什么样、容量多大：

  • 网络层数（Depth）：隐藏层的数量（如 ResNet-18 vs ResNet-50）。
  • 每层的神经元数量 / 通道数（Width/Channels）：例如卷积层输出的通道数（16, 32, 64...）。
  • 激活函数（Activation Function）：如 ReLU、GELU、LeakyReLU 的选择。
  • Dropout 比例：训练时随机丢弃神经元的概率（如 0.2、0.5），用于防止过拟合。

6.7.1.2 为什么叫“超”参数？

这里的“超（Hyper-）”表示元（Meta）或更高层级的意思。

因为它们超越了模型自身的学习机制，是在定义“模型的学习规则”和“模型的容量边界”。模型在训练时，只能在其给定的超参数框架内去求解最优的参数（权重 \(w\) 和偏置 \(b\)）。

6.7.1.3 常见调优方式（调参 / Hyperparameter Tuning）

找到一组优秀的超参数通常是深度学习实验中最耗费时间的工作之一，常见的调优策略包括：

  1. 网格搜索（Grid Search）：穷举法。在预先设定的参数组合列表里遍历测试所有可能（耗时极长）。
  2. 随机搜索（Random Search）：在参数空间内随机抽样组合。通常比网格搜索更高效，能更快覆盖更大的搜索空间。
  3. 贝叶斯优化（Bayesian Optimization）：根据已测试组合的结果，用概率模型预测下一组最有潜力的超参数组合（自动化调参库如 Optuna、Ray Tune 常用的核心策略）。
  4. 凭经验与手动调整（Intuition / Manual Tuning）：根据训练/验证集的 Loss 曲线和评估指标，人工手动修正（例如 Loss 震荡不收敛则调小学习率，发生严重过拟合则加大 Dropout 或 Weight Decay）。

6.7.2 argparse是什么

如上所述，深度学习中超参数有很多，如何对它们进行有序管理与组织是个要关注的问题，因为超参数是深度学习实验中很重要但也也很耗时的工作，可能需要我们经过多次试验才能找到一组合适且高效的超参数组合。

大多数超参数需要在训练过程中根据训练结果进行尝试性改进，比如说学习率这个超参数（其他很多超参数也类似），可能需要在前一次或多次实验结果的基础上进行分析与修改（比如）；另外个别超参数，如 随机种子 一般需要在训练过程中保持固定不变，以确保训练过程和实验结果的可复现性。

这一大批超参数如何传入、如何解析、有没有合理的提示、有没有进行类型等检查，最好能统一的管理起来。Python已经原生内置了argparse这个模块来完成上述参数的传入与管理工作（深度学习中的超参数本质上也是程序参数，刚好利用上它）。 注意，除了利用argparse来管理传入的超参数，有时为了保证训练的连贯性还需要进行超参数的保存。

argparse 模块让编写用户友好的命令行接口变得容易。 程序定义它需要哪些参数，argparse 将会知道如何从 sys.argv 解析它们。 argparse 模块还能自动生成帮助和用法消息文本。 该模块还会在用户向程序传入无效参数时发出错误提示。

6.7.3.3.2 重点讲述action与default参数

在 ArgumentParser.add_argument() 中同时传入 action 与 default 参数时，行为完全取决于 action 的具体类型。

最常见的几种情况如下：

1. action="store_true" 或 action="store_false"

这是布尔开关。是最常见同时使用 default 的场景。

  • 原理：
    • 当用户在命令行显式传入该参数标志时，触发指定的动作（设为 True 或 False）。
    • 当用户在命令行未传入该参数标志时，直接使用 default 指定的值。

注意：如果不显式写 default，store_true 默认的 default 本身就是 False，store_false 默认的 default 本身就是 True。但显式指定 default 能让代码意图更清晰，或者在特殊需求下反向定义（例如将 action="store_true" 的 default 设为 None，以区分“用户未传”与“用户显式关闭/开启”）。

2. action="store"（默认动作，存入单一值）
  • 原理：store 是默认动作。如果命令行指定了该参数，则保存用户给定的值；如果命令行未指定，则保存 default 的值。
3. action="append"（追加到列表）
  • 原理：每次在命令行遇到该参数时，将值追加（append）到列表中。
  • 与 default 的冲突点/易错点：
    • 未指定参数：变量值为 default 的原始值（建议设为列表或 None）。
    • 指定参数：用户传入的值会追加在 default 列表的末尾，而不会覆盖 default 列表！

最佳实践：如果使用 action="append"，通常建议设置 default=None 或在解析后再做判定，避免默认列表被污染。

4. action="count"（统计出现次数）
  • 原理：统计标志在命令行出现的次数（常用于日志详细程度 --verbose 或 -vvv）。
  • 行为：
    • 未传入时，变量值为 default。
    • 传入 \(N\) 次时，变量值为 default + N（如果 default 为整型）或直接计数（如果 default=None，首次出现从 1 开始计）。
5. action="store_const"（存储常数）
  • 原理：当指定参数标志时，将 const 参数赋予的值存入；未指定时，存入 default 的值。
总结对照表
action 类型 命令行未指定参数时 命令行指定参数时 注意事项
store (默认) 结果为 default 结果为 用户输入值 最标准的默认值覆盖策略
store_true 结果为 default (默认 False) 结果为 True 常用作功能开关
store_false 结果为 default (默认 True) 结果为 False 常用作禁用开关
append 结果为 default 在 default 列表后追加 若 default 是列表，不会被覆盖，只会追加
count 结果为 default 结果为 default + 出现次数 用于统计出现频次
store_const 结果为 default 结果为 const 值 必须配置 const 参数
