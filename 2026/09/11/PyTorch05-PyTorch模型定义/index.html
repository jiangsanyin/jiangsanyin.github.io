五、PyTorch模型定义

5.1 PyTorch模型定义的方式

我们会在不同场合看到多种不同的模型架构，比如 CNN（Convolutional Neural Network，卷积神经网络）、RNN（Recurrent Neural Network，循环神经网络）、GNN（Graph Neural Network，图神经网络），它们是深度学习领域针对不同数据结构设计的神经网络架构，分别用来解决网格化结构数据（如二维图像、视频帧）的局部特征提取与空间感知问题、序列数据（如文本、语音、时间序列）的前后关联与时序依赖问题、以及非欧几里得图结构数据（如社交网络、分子结构、知识图谱）的复杂关系建模问题。

在实际应用中，每种宏观架构下都有诸多经典的具体模型实现。在学习或使用这些模型时，通常需要先理解其内部的运行机制。本章节将基于 PyTorch 这一深度学习框架，从粗略地角度来探索与学习下模型的代码实现与构造方式。

本章节学习的内容包括：使用PyTorch定义模型的三种经典方式。

5.1.1 必要的知识回顾

在PyTorch 中，torch.nn.Module是一个基本构造类，所有神经网络层（如 nn.Linear、nn.Conv2d）以及自定义的大模型，本质上都是它的子类。 当我们基于torch.nn.Module来自定义模型时，一般就是要重写自定义类的__init__与forward两个方法。

在基于torch.nn.Module来构建自定义模型组成与执行流程的具体实现时，可以借助Sequential或 ModuleList或ModuleDict 这三个类（它们是官方提供且最常用的，但并不是 PyTorch 定义模型子模块的“唯三”方式）。其他的常用的方式还有：给自定义类的属性赋值然后在forward方法中调用。通常在编写较复杂的网络时，是将“直接类属性定义”与 Sequential、ModuleList、ModuleDict 混合配合使用的。

以下分别对这三个类及使用进行精简介绍并给出示例。 ### 5.1.2 定义模型子模块的常用三个类

5.1.1.2 Sequential

nn.Sequential 是 PyTorch 中最简单的模型容器。它按照层添加的顺序依次执行前向传播，无需手动编写 forward() 函数。因此它无法应对条件分支、跳连、多分支等复杂结构，只适合于结构简单、顺序执行的模型。 它可以接收一系列子模块或子模块的有序字典(OrderedDict)，从而给模型逐一添加 Module 的实例，且按它们出现的顺序作为模型前向传播时的执行顺序。

5.1.1.3 ModuleList

nn.ModuleList 接收一个子模块（或层，要是nn.Module类）的列表作为输入，但nn.ModuleList并没有直接定义一个完整的模型（无法自动进行前向传播），它只是将不同的子模块或层储存在一起，并将子模块或层的权重也会自动添加到模型中。要想让它像模型一样工作还需手动遍历其中所有层或子模块（即列表中所有元素）并执行它们。

对于一个nn.ModuleList 实例，可以操作Python中普通的列表List一样对其增加、扩展、删除、索引与修改元素。

5.1.3 三种方法的比较与适用场景

nn.Sequential 适用于结构简单、单线顺序执行的网络或子网络。它的优势在于能自动处理层与层之间的数据传递，无需在 forward 中逐层手写连接逻辑；ß但无法直接支持跳连、多分支和动态条件判断。

nn.ModuleList 和 nn.ModuleDict 则适用于需要动态选择、遍历堆叠或分支切换的复杂网络结构。它们主要起 “安全注册参数”和“容器管理” 的作用，具体的跳连、分支以及数据流向逻辑，必须在自定义模型的 forward() 中手动编写实现。

容器类型 自动执行 forward 适用场景 关键局限性
nn.Sequential 是 单线流水线结构、无分支/无跳连、快速搭建局部子网络（如 MLP、经典 CNN 骨干） 无法支持多输入/多输出、条件分支、跳连（如 ResNet）
nn.ModuleList 否 需要按索引访问层、循环堆叠大量相同 Block（如 Transformer 编码器层）、动态选择执行某些层 必须在自定义 forward 中用 for 循环手动调用每一层
nn.ModuleDict 否 需要根据名称（字符串 Key）动态调用不同分支（如多任务学习中的不同 Head、多数据集适配器） 必须在自定义 forward 中通过 Key 手动查找并调用对应模块

5.2 利用模型块快速搭建复杂网络

到目前为止，所学的知识下，都是利用torch.nn包下的相关类来直接定义模型，如Sequential、ModuleList、ModuleDict等。但当模型结构比较复杂、导数很多时，直接使用它们当然可以完成模型的定义，但层层不断地堆叠子模块或层会使得模型的可读性与复用程度很低。通过阅读前面学习过的多个规模的ResNet模型的具体实现可以发现，其中一直在复用两个模块：BasicBlock、Bottleneck，这就是模型块。

复杂、多层的模型中往往会重复出现类似的层或子模块，它们都会有输入与输出。将输入输出、结构重复或类似的层或子模块进行抽象，就形成了模型块。复杂、多层的模型一般利用模型块来进行实现，减少了代码量同时也提升了模型的可读性。

本章节以U-Net模型为例，讲述模型结构的特征或规律、如何构建模型块、如何利用模型块构建复杂模型（这些也就是本章节的学习内容）。

5.2.2 U-Net模型结构分析

从上图可以看到，UNet模型的结构在垂直方向可以分为几层；除了最底层的其他的层，每层都有左右两个部分；对于中间层，左右部分都与其上层或下层的部分存在连接，对于最上层或最底层，仍在反方向与其他部分存在连接；对于中间层，左右两个部分之间还存在一条跳跃连接路径。UNet整个模型结构图像是一个U型，这也是此模型被称为UNet的缘由。

再明确大致分析下其结构特点： - 每层的左侧部分都会进行两次卷积操作。===>可封装成一个模型块DoubleConv。 - 每层中（除了第一层），与相邻的部分之间会进行一次最大池化以进行一次下采样，再连续进行两次卷积（可复用DoubleConv）。===>可封装成一个模型块Down。 - 每层中的右侧部分，都会进行一次上采样，并与同一层的左侧部分输出执行跳跃连接操作，最后再连续进行两次卷积操作。===>可封装成一个模型块Up。 - 模型的最后输出是用与多个(1,1)卷积核做卷积得到的每个分类的原始得分。===>可单独封装成一个子模型块OutConv。

这是对UNet模型的结构分析，及尝试封装成对应的模型块。其他实现细节此处不展开。

5.2.3.2 转置卷积操作

这个实现中涉及到一个新的概念，叫转置卷积操作，也叫反卷积，也常被称作上采样。与前面经常使用的下采样基本上可以看作是互逆的操作（但非严格互逆）。

nn.ConvTranspose2d 是 PyTorch 中的二维转置卷积操作（Transposed Convolution），在学术界和工程中也常被称为 “反卷积”（Deconvolution） 或 “上采样卷积”。

它的核心作用与标准卷积（nn.Conv2d）刚好相反：标准卷积通常用于“下采样”（提取特征、缩小图像尺寸），而转置卷积用于“上采样”（放大特征图分辨率、恢复空间细节）。

5.2.3.2.1 为什么叫“转置”卷积？

标准卷积在数学运算时，可以写成矩阵乘法 \(Y = C \cdot X\)（其中 \(C\) 是根据卷积核构建的稀疏矩阵）。 而转置卷积在数学上的前向传播，相当于使用了标准卷积矩阵的转置矩阵 \(C^T\) 进行计算（即 \(Y = C^T \cdot X\)），因此得名“转置卷积”。

5.2.3.2.2 工作原理（直观理解）

转置卷积并不是简单地把卷积过程逆转恢复出原始像素，而是一种带可学习参数的图像放大技术。

  1. 补白（Padding / Stride 扩展）：在输入特征图的元素之间插入空白（零填充），拉开像素间距。
  2. 卷积滑动：用可学习的卷积核在扩展后的特征图上进行标准卷积滑动。
  3. 输出放大：最终生成一个长宽尺寸更大的特征图。
5.2.3.2.3 维度计算公式

给定输入尺寸 \(H_{in}\)，转置卷积输出的尺寸 \(H_{out}\) 计算公式如下： \[H_{out} = (H_{in} - 1) \times \text{stride} - 2 \times \text{padding} + \text{kernel\_size} + \text{output\_padding}\] 最常见的 2 倍上采样配置（放大 2 倍）：

当设置 kernel_size=2, stride=2, padding=0 或 kernel_size=4, stride=2, padding=1 时，输出图像的长宽正好是输入的 2 倍。

5.2.3.2.4 适用场景与局限性
  • 经典应用场景
    • UNet / FPN：在 Segmentation 的 Decoder 部分用于逐步恢复图像分辨率。
    • GAN（生成对抗网络）：生成器（Generator）用来从低维随机噪声逐步生成高分辨率图像。
    • Diffusion（扩散模型）：在主干 UNet 的上采样阶段放大特征图。
  • 局限性：棋盘效应（Checkerboard Artifacts）
    • 由于转置卷积的卷积核在放大后的网格上重叠覆盖不均匀，容易导致生成的图像出现类似棋盘的微小网格斑纹。
    • 替代方案：在现代工程中，常使用 nn.Upsample(mode='bilinear') + nn.Conv2d 的组合来代替 ConvTranspose2d，这种组合既能平滑放大图像，又能完全避免棋盘效应。

5.3 PyTorch修改模型

利用PyTorch，虽然我们可以从零开始构建模型，但有时这样从零开始可能会比较低效，尤其是我们想做快速验证时。此时我们可以挑选一些使用场景跟自己类似的开源模型，以其为基础进行修改、二开，修改原开源模型的结构或输入或输出，使其满足我们的需求。

此章节讲述如何修改基于PyTorch的模型，讲述的内容包括：修改模型层、添加额外输入、添加额外输出。 不管是如何修改原模型，首先要掌握原模型的使用场景、优缺点与结构和前向传播过程。在确定了原模型后，熟练了解原模型结构和前向传播过程对于自定义模型是非常有必要的。

5.3.1 修改模型层

本节以官方视觉库torchvision中内置的ResNet-50模型为基础，讲述如何修改模型层。

根据对resnet-50的了解及上述代码执行时输出内容可以看到，官方原resnet-50的最后一层是一个名为fc的层，其只有一个子层为全连接层，接收2048个输入特征、产生1000个输出特征（这1000个特征刚好对应于1000个不同类别物品。resnet-50是在著名的 ImageNet (ILSVRC-2012) 大规模图像分类数据集上训练的，该数据集刚好包含 1000 个常见的日常物体类别（比如各种品种的狗、猫、车辆、水果、水果、电子产品等））。

在resnet-50现有官方实现的基础上，我想对其进行少量的改造使其能够做一个10分类的问题。最简单的方法就是对其现有的fc层进行改造。我们不使用的一层全连接操作，因为它无法解决稍微复杂点的问题（如异或问题），暂时也没有必要直接堆叠多个全连接层，所以此处暂时保采用两个全连接层，中间包含激活层与Dropout层。

通过nn.Sequential与collections.OrderedDict将一系列简单的层组合起来，将最终的nn.Sequential实例直接赋值给net.fc即可实现上述改造目的。

5.3.2 添加额外输入

在基于开源或已有模型的基础上，来改造、训练自己的新模型时，原有模型的原有训练数据可能还能利用，但需要再添加一些额外的信息，此时在原有模型的工作流程过程中插入新模型的相关数据与流程。 为什么还要继续使用原有训练数据呢？因为成本、必要性等因素不想直接对原有训练数据进行再构建。此时我们可以在原模型前向传播到某个步骤时，添加额外的输入甚至与原模型当时的中间产生数据进行融合，并根据情况自定义后续的处理流程。

基本的思路是：将原模型添加额外输入前的部分作为一个整体继承或保留到新模型中，接收额外输入，根据新模型的需求构建额外输入与剩下流程之间的衔接与定义。
一般来说，新模型是通过继承torch.nn.Module来自定义，将原模型实例当成一个参数传递给新模型的__init__方法并对此方法中定义好新模型中需要的各模块与层，同时新模型的forward方法会接收那个额外输入后将其应用于新模型的前向传播过程中（再次说明需要对原模型的结构与前向传播过程很熟悉）。

5.4 PyTorch模型保存与读取

基于PyTorch构建好模型，训练后达到一定效果后，可以将其保存下来，以便后续直接恢复训练得到的模型及效果。 本章节学习如何进行PyTorch模型的保存与读取。以下都是基于PyTorch这一机器学习与深度学习框架而言，具体包含的内容有：模型的存储格式、模型的存储内容、单卡或多卡下模型的存储与加载、模型权重外其他参数的存取。

5.4.1 模型存储内容

PyTorch 模型主要包含两个部分：模型结构和模型权重（状态参数）。保存 PyTorch 模型时，通常有两类方式：保存整个模型架构，或仅保存模型权重。这两者都是通过 torch.save() 方法来实现的，区别仅在于传入的保存对象不同。

在 PyTorch 中，自定义模型通常继承自 torch.nn.Module。模型结构是由在 __init__ 中定义的各个子模块或层（如卷积层、全连接层）所构建的计算图网络；而模型权重则是指这些子模块或层中的参数张量（Tensor），主要保存在模型的 state_dict（状态字典）中。这些权重既包含在训练过程中通过反向传播和优化器更新的可训练参数（Parameters，如权重与偏置），也包含在前向传播中动态更新的缓冲状态（Buffers，如 BatchNorm 的运行均值与方差）。

这说明：torch.save() 根据“被保存的对象”和其序列化规则写入内容，不会因为路径后缀是 .pth、.pt 或 .pkl 而切换格式。加载时也不需要“后缀匹配”，例如这个文件即便改名为 .abc即使用torch.load("resnet-50.abc", weights_only=False)，仍可用。

实践中一般选一种统一命名（常见为 .pth 或 .pt），并优先保存 state_dict()；后缀本身不提供额外兼容性或压缩效果。
